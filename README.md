## 📖 Overview

Antibiotic susceptibility testing traditionally requires **24–72 hours** of bacterial culture. **MALDI-TOF mass spectrometry** — already present in most hospital microbiology labs — produces a bacterial "protein fingerprint" in *minutes*. This project asks: **can we read antimicrobial resistance directly from that fingerprint with machine learning?**

**AMR Prediction System** is a **3-tier web application** that does exactly that. It takes a raw MALDI-TOF spectrum (6,000 intensity bins), runs it through a leak-free preprocessing + classification pipeline, and returns a resistance prediction **plus a clinician-readable interpretation report** generated by a LangChain + Google Gemini **RAG** layer. It is built on the public **[DRIAMS-A dataset](https://datadryad.org/stash/dataset/doi:10.5061/dryad.bzkh1899q)** (~11,500 clinical isolates, 2015–2018).

> ⚕️ **Decision-support, not diagnosis.** Predictions are a fast screening signal and must be confirmed by phenotypic AST before any clinical decision.

---

## ✨ Key Features

- **End-to-end 3-tier system** — Streamlit dashboard → FastAPI REST API → ML + RAG engine.
- **Rigorous, leak-free ML** — preprocessing (scaler/PCA) is **re-fit inside every cross-validation fold**, so reported metrics are honest.
- **Clinically-tuned thresholds** — per-species decision thresholds optimized on out-of-fold probabilities for best F1 under a false-positive-rate cap.
- **Class-imbalance aware** — SMOTE **or** cost-sensitive class weighting (never both), chosen by prevalence.
- **RAG clinical reports** — grounded, structured markdown reports via Gemini; **fully offline fallbacks** keep the app usable with no API key/internet.
- **Responsible ML** — statistically unreliable targets are flagged `data_limited` and shipped with an unmissable "NOT A VALIDATED MODEL" banner.
- **Real demo data** — ground-truth-labeled DRIAMS-A isolates included in [`test_spectra/`](test_spectra/).

```
┌──────────────▼───────────────┐   ┌─────────────▼──────────────────┐
│  TIER 3a — ML ENGINE          │   │  TIER 3b — AI / RAG ENGINE      │
│  ml_pipeline/                 │   │  langchain_engine/              │
│  TIC → √ → VarThresh → Scaler │   │  embed guidelines → cosine      │

└───────────────────────────────┘   └─────────────────────────────────┘
        scikit-learn + joblib               Google Gemini API
```

**Why 3 tiers?** Separation of concerns, independent scaling, and reuse — the UI can be swapped without touching models, the API can serve other clients, and the ML engine is plain, testable Python.

## 🔬 How It Works

### 1 · Preprocessing (`ml_pipeline/preprocessing.py`)
Each 6,000-bin spectrum passes through a scikit-learn `Pipeline`:

| Stage | Transform | Why |
|-------|-----------|-----|
| TIC normalization | divide by total ion current | removes instrument batch effects, preserves peak ratios |
| √ variance stabilization | `sqrt` | compresses MALDI-TOF's extreme peak skew (E. coli ROC-AUC +~0.015) |
| VarianceThreshold | drop near-zero-variance bins | remove uninformative baseline noise |
| StandardScaler | zero-mean / unit-variance | PCA is scale-sensitive |
| PCA (95% variance) | dimensionality reduction | 6,000 bins → ~1,350–1,680 components |

Labels are binarized **S→0, R→1**; Intermediate ("I"), untested, and replicate-discordant results are **dropped** (EUCAST defines "I" as pharmacologically distinct from resistant).

### 2 · Modeling & validation (`training.py`, `threshold.py`)
- Five candidates benchmarked per target — **SVM (RBF), XGBoost, LightGBM, CatBoost, AdaBoost** — best chosen by cross-validated **F1**.
- **5-fold stratified CV** with the **entire preprocessing pipeline re-fit inside each fold** → no data leakage.
- **Class imbalance:** SMOTE inside training folds *(prevalence < 5%)* **xor** cost-sensitive class weights — never stacked.
- **Threshold optimization** on leak-free out-of-fold probabilities: best F1 with **FPR ≤ 10%**.
- **Temporal holdout:** train ≤ 2017, test on 2018 (mirrors real deployment).

### 3 · Clinical report (`langchain_engine/`)
Retrieval-Augmented Generation: guideline sections are embedded (`text-embedding-004`), the top match is retrieved by **cosine similarity**, injected into a prompt, and `gemini-2.5-flash` produces a structured report (summary · ML insight · therapeutic actionability · infection control). If no API key/internet is available, a templated offline report is compiled from the same guidelines.

## 📈 Model Performance

Honest leak-free cross-validation metrics (viewable live in the dashboard's **Model Performance** tab):

| Pathogen / Antibiotic | Model | Threshold | ROC-AUC | F1 | Recall | Major Err (FPR) | Very Major Err (FNR) |
|-----------------------|-------|:---------:|:-------:|:--:|:------:|:---------------:|:--------------------:|
| *S. aureus* / Oxacillin | SVM | 0.50 | 0.922 | 0.725 | 0.696 | 5.3% | 30.4% |
| *E. coli* / Ceftriaxone | SVM | 0.45 | 0.892 | 0.715 | 0.667 | 5.5% | 33.3% |
| *K. pneumoniae* / Meropenem ⚠️ | SVM | 0.15 | 0.961* | 0.400* | 0.375* | 0.4% | 62.5% |

> **⚠️ `data_limited`:** *K. pneumoniae / Meropenem* has only **24 resistant isolates (~0.85%)** in the entire dataset. Any metric derived from ~5 positives per fold is statistically meaningless — this target is **not a validated model** and is retained only to demonstrate the pipeline on an extreme-imbalance case.

**Clinical error framing:** a **Major Error (FPR)** is predicting Resistant when Susceptible (unnecessary strong therapy); a **Very Major Error (FNR)** is predicting Susceptible when Resistant (ineffective treatment — potentially fatal). The pipeline is tuned to keep FNR low.

## ⚡ Quick Start

### 1 · Prerequisites
- **Python 3.10+**
- *(Optional)* a free **[Google Gemini API key](https://aistudio.google.com/app/apikey)** — without it, the app runs with offline report fallbacks.

### 2 · Clone
```bash
git clone https://github.com/tygopal45/Antimicrobial_Resistance_Prediction_Model_SuperBug_Shield.git
cd Antimicrobial_Resistance_Prediction_Model_SuperBug_Shield
```

### 3 · Install
```bash
# macOS / Linux
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```
```powershell
# Windows
python -m venv .venv; .venv\Scripts\activate
pip install -r requirements.txt
```

### 4 · Configure (optional API key)
```bash
cp .env.template .env      # then edit .env:
# GEMINI_API_KEY=your_actual_api_key_here
```

### 5 · Run (two terminals)
```bash
# Terminal 1 — backend (wait a few seconds for models to load)
uvicorn fastapi_backend.main:app --host 0.0.0.0 --port 8000

# Terminal 2 — frontend
streamlit run streamlit_app/app.py --server.port 8501
```

### 6 · Open
| Service | URL |
|---------|-----|
| 🖥️ Streamlit Dashboard | **http://localhost:8501** |
| 📚 FastAPI Docs (Swagger) | http://localhost:8000/docs |

Upload a spectrum from [`test_spectra/`](test_spectra/) (real DRIAMS isolates with known labels) and click **Run AMR Prediction**.

## 🚀 Deploying to Render

The project is modularised into two independent services with a root `render.yaml` blueprint:

| Directory | Service | Runtime |
|-----------|---------|---------|
| `backend/` | FastAPI inference API | Python (uvicorn) |
| `frontend/` | Streamlit dashboard | Python (streamlit) |

### Step 0 — Handle large model files (CRITICAL)

The trained `.joblib` files total ~300 MB. GitHub limits single files to **100 MB**. You have two options:

**Option A — Git LFS (recommended for Render free tier):**
```bash
# Install Git LFS once
git lfs install

# Track all joblib files
git lfs track "*.joblib"
git add .gitattributes

# Stage and commit the model files
git add ml_pipeline/models/*.joblib
git add data/processed/*.joblib
git commit -m "feat: add trained models via Git LFS"
git push origin main
```
> Render automatically pulls Git LFS files during build — no extra config needed.

**Option B — Render Disk (requires Render paid plan):**
Skip committing model files. Attach a Render Disk to the backend service, mount it at `/mnt/models`, upload files via Render Shell, and set:
```
MODELS_DIR=/mnt/models/ml_pipeline/models
PROCESSED_DATA_DIR=/mnt/models/data/processed
```

```bash
cd "Bacterial Resistance"
```

### Step 2 — Deploy on Render via Blueprint

1. Go to [render.com](https://render.com) → **New** → **Blueprint**
2. Connect your GitHub account and select this repository
3. Render auto-detects `render.yaml` and shows **two services**: `amr-backend` and `amr-frontend`
4. Click **Apply** — both services start building

---

### Step 3 — Set Secret Environment Variables

After services are created, go to **each service → Environment** in the Render dashboard:

**For `amr-backend`:**

| Variable | Value |
|----------|-------|
| `GEMINI_API_KEY` | Your Google AI Studio key |
| `ALLOW_ORIGINS` | `https://amr-frontend.onrender.com` (replace with your frontend URL) |

**For `amr-frontend`:**

| Variable | Value |
|----------|-------|
| `BACKEND_URL` | `https://amr-backend.onrender.com` (replace with your backend URL) |

> You can find the auto-generated Render URLs in each service's dashboard page.

---

### Step 4 — Trigger a Redeploy

After setting env vars, click **Manual Deploy → Deploy latest commit** on both services.
